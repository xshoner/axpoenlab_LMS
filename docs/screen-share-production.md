# LMS 화면 공유

슈퍼관리자 상단의 **미리보기 왼쪽 → 화면공유**를 사용한다. 기수를 선택하고 브라우저의 화면 선택 창에서 탭, 창 또는 전체 화면을 선택한다. 해당 기수의 로그인한 학생에게 공유 화면이 자동 표시된다. **공유해제** 또는 브라우저의 공유 중지를 누르면 모두 연결을 종료하고 학생은 기존 LMS 화면으로 돌아온다. LMS의 페이지와 입력 상태를 유지한다.

## 연결과 비용

- 로그인과 대기 중에는 Daily SDK 로딩, Daily 입장, 토큰 발급을 하지 않는다. Supabase의 세션 알림과 조회만 사용한다.
- 슈퍼관리자의 화면 선택이 성공한 뒤 교사 연결을 만들고, 실제 송출 시작 후 학생에게 연결을 허용한다. 학생·관리자는 공유를 시작하거나 종료할 수 없다. 관리자 미리보기 모드에서도 사용할 수 없다.
- 오디오와 카메라를 캡처하지 않는다. 서버 토큰도 교사에게 화면 영상 송출만 허용하고 학생에게 송출 권한을 주지 않는다.
- 종료 즉시 학생 세션 알림을 해제하며, Daily 서버에서도 입장 마감과 참가자 강제 퇴장을 요청한다. 발급 전 모든 토큰 수신자 ID를 서버 전용 테이블에 기록하고 전원을 퇴장시킨다. Daily REST 참가자 스냅샷은 갱신이 늦을 수 있으므로 이를 종료 완료의 즉시 판정으로 사용하지 않는다. 강제 퇴장 API가 성공한 뒤 종료 상태를 확정하며, 실패하면 방 잠금을 유지하고 watchdog으로 재시도한다.
- 교사 탭 종료 시 keepalive 종료 요청을 전송한다. 교사 15초 heartbeat, LMS 45초 lease와 서버의 30초 주기 watchdog을 둔다. 교사 연결이 사라지면 학생의 LMS 연결 감시 및 서버 강제 퇴장으로 종료한다. 브라우저 강제 종료 시 서버의 최초 정리 시도는 마지막 정상 heartbeat 이후 최대 약 75초에 시작된다. Daily API 장애 시 다음 정리 주기에 재시도하므로 종료가 지연될 수 있다.
- Daily는 입장 시 참가자의 만료 시각을 고정하므로 짧은 방 만료를 반복 갱신하는 방식은 기존 참가자의 연결을 연장하지 못한다. 정상 수업 중 조기 종료를 방지하기 위해 방의 최종 만료는 8시간으로 두고, 짧은 연결 만료는 watchdog이 담당한다. 8시간을 넘는 연속 공유는 새로 시작한다. Supabase와 Daily API가 동시에 장기간 장애인 경우에는 이 방 만료가 최종 안전장치다.
- 상단 **이달 N 인·분**은 한국 시간 기준 월 누적 접속 인원×분 추정치다. 15초 단위 참가자 수 표본으로 계산하므로 Daily 청구서와 정확히 일치하지 않는다. 여러 탭에서 학생이 접속하면 각 연결이 인원으로 계산될 수 있다.
- 토큰 요청 10초, SDK 로딩·입장 각각 15초, 교사 영상 미수신 15초, 영상 재생 대기 10초, 네트워크 복구 30초에 제한한다. 짧은 네트워크 끊김은 SDK가 복구하되 복구되지 않는 연결은 종료한다. 같은 공유의 자동 입장 시도는 최대 3회이며 이후 학생이 **다시 연결**을 눌러 재시도한다. 실패 시 LMS 화면 잠금을 해제한다.
- 브라우저 종료 처리에서는 즉시 `leave`와 `destroy`를 시작하고 캡처 트랙·타이머를 제거한다. 취소 뒤 완료된 서버 시작이나 SDK 입장도 추가 정리한다. 서버 정리 작업은 90초, DB 정리 잠금은 120초이며 watchdog HTTP 요청은 120초까지 기다린다. 정리에 실패한 공유와 만료 공유는 운영 현황에서 별도로 확인한다.

## 방과 학생 표시

고정 방 `https://axopenlab.daily.co/axopenlab20261001`을 모든 기수에 재사용한다. 하나의 활성 공유만 허용하며, 토큰은 30초 동안 입장 가능하다. 이전 기수 토큰으로 다음 기수 공유에 입장하지 못하도록 마지막 토큰 발급 이후 최대 35초간 재시작을 막는다. 토큰 만료 자체로 시청 중인 학생을 퇴장시키지는 않는다.

학생에게는 브라우저 콘텐츠 영역 전체를 덮는 영상 화면을 표시하며 축소·종료·오디오 메뉴가 없다. 브라우저 보안 규칙상 사용자 동작 없는 OS 전체화면 진입은 보장할 수 없다. 공유 화면은 영상 자동 재생이 허용되는 음소거 영상이다. 서버 권한은 선택된 기수의 활성 학생만 허용한다. 로그인하지 않은 사람과 다른 기수, 관리자에게 Daily 토큰을 발급하지 않는다.

## 서버 구성과 배포

Supabase 프로젝트: `ugelgndotyppgksbubot`. Edge Secret `DAILY_API_KEY`가 필요하다. 프런트엔드 환경변수나 GitHub에는 키를 넣지 않는다. `screen-share` Edge Function은 JWT를 `auth.getUser`로 검증하고 실제 활성 프로필 및 기수 소속을 서버에서 검사한다. 게이트웨이 JWT 검증 비활성화는 이 인증 검증을 대신하지 않는다. watchdog 전용 무작위 키를 Edge Secret `DAILY_SCREEN_SHARE_WORKER_KEY`와 Supabase Vault `screen_share_worker_key`에 동일하게 등록한다. 이 키는 내부 만료 정리에만 사용할 수 있고 사용자 토큰 발급이나 공유 시작에는 사용할 수 없다.

1. `20261002010000_screen_share.sql`, `20261002020000_screen_share_watchdog.sql`, `20261002030000_screen_share_admissions.sql`, `20261002040000_screen_share_server_time.sql` 마이그레이션을 순서대로 적용한다. 기존 데이터는 수정하지 않는다. 서비스 역할만 공유 상태를 변경할 수 있다. watchdog 마이그레이션은 hosted Supabase의 `pg_cron`/`pg_net`을 활성화하고 30초 작업을 등록한다. 종료할 세션이 없는 대기 중에는 HTTP/Daily API를 호출하지 않는다.
2. `npx supabase functions deploy screen-share --project-ref ugelgndotyppgksbubot --use-api --no-verify-jwt`
3. `npm ci`, `npm run lint`, `npm run test:screen-share`, `npm run test:tenancy`, `npm run build`
4. 운영 Vercel 프로젝트 `lms-axopenlab`에 프런트엔드를 배포한다.

수동 SQL 적용 시 Supabase 마이그레이션 이력에도 동일 버전을 기록해야 한다. 관련 없는 미적용 마이그레이션을 함께 실행하지 않는다. 공개 테스트 사이트에서 직접 같은 방에 입장하던 방식은 운영의 비공개 방/서버 토큰 방식과 다르므로 운영 시연에는 LMS 버튼을 사용한다.

## 확인 항목

자동 테스트는 로그인 시 연결 없음, 교사 화면 선택 취소, 공유 시작 순서, 학생 무조작 입장/종료, 종료와 토큰 발급 경합, 교사 이탈 후 빈 방 재입장 차단, 서버 역할·기수 권한, RLS, 단일 방 잠금, 재시작 대기, 월 사용량 계산을 검사한다. 실제 브라우저에서는 Daily 영상 송출과 학생 음소거 자동 재생, 다른 기수 미연결, 종료 후 LMS 복귀를 확인한다.

2026-10-06 보강: `20261006010000_preserve_assignment_files.sql`과 `20261006020000_share_cleanup_monitor.sql`만 추가 적용한다. 기존 운영 행과 파일을 변경·삭제하지 않는다. 첫 마이그레이션은 현재 제출물·과거 버전이 참조하는 파일의 삭제/덮어쓰기를 막고, 둘째는 종료 감시 시간과 운영 조회를 보강한다. 서버 함수를 반영한 뒤 프런트엔드를 배포한다.

공유 만료는 서버가 계산한 남은 시간과 브라우저의 단조 증가 시간으로 판단한다. 학생 PC의 시계가 서버와 달라도 자동 연결되며, 조회 RPC는 기존 RLS와 기수 권한을 유지한다.
