## 기존 데이터 보존

기존 행의 소유권을 추정해서 다른 관리자에게 넘기지 않는다. 추가한 `owner_admin_id`의 기존 값은
`NULL`이며 기존 슈퍼관리자 운영 영역을 뜻한다. 기존 강좌 본문, 회원, 기수, 코드, 파일,
설문 응답, 퀴즈 답안 등을 갱신하거나 삭제하는 백필은 없다. 새 행의 소유권은 DB 트리거가 기록한다.

마스터와 복사본의 강좌·과제·설문·퀴즈 구성은 별도 행이다. 첨부 파일의 바이트는 기존 스냅샷 방식과
같이 공유하지만, 참조 중인 강좌/공지 파일은 덮어쓰기·삭제할 수 없다. 첨부 연결 삭제는 원본 파일을
지우지 않는다. 기존 게스트 토큰도 변경하지 않는다.

## 서버 검증

- 기존 RLS 정책과 AND로 결합되는 제한 정책을 모든 관리 대상 테이블에 추가한다.
- RPC 목록·정렬·복사·편집은 RLS를 적용하고, 채점·집계 등 SECURITY DEFINER 함수는 소유권을 명시적으로 확인한다.
- `admin-users`의 service-role 작업은 활성 역할과 대상 회원의 기수 소유자를 확인한다.
- 슈퍼관리자의 `x-admin-view` 헤더는 접근 범위를 좁히는 데만 사용한다. 일반 관리자가 같은 헤더를 보내도 다른 관리자 권한을 얻지 못한다.
- 공용 Presence 채널 대신 서버가 집계하는 heartbeat를 사용한다. 30초 간격 갱신, 90초 만료이며 학생 식별자를 공개 채널에 전송하지 않는다.
- 명시적으로 입력한 가입 코드를 서버에서 먼저 검증하고 배정한다. 기존 공통 가입 설정은 빈 코드에만 적용한다.
- 개인 임시저장과 기수 선택은 사용자별로 분리한다.

## 검증

```sh
npm run lint
npm run test:tenancy
npm run build
```

`test:tenancy`는 외부 서버에 연결하지 않는다. PGlite의 실제 PostgreSQL 엔진에 전체 마이그레이션을
실행하고 서로 다른 관리자·학생·슈퍼관리자 역할로 테스트한다. 기존 행의 원래 컬럼 값을 마이그레이션
전후 비교하고, 배포 중 실패를 주입해 스키마와 권한이 모두 롤백되는지 검사한다.
Edge Function 테스트는 실제 핸들러를 실행하며 인증/DB 어댑터만 테스트용으로 대체한다.

검증 범위: 교차 관리자 조회·쓰기, 소유자 위조, 코드 가입, 마스터 보호·복제, 파일 경로 위조,
설문 제출, 퀴즈 정답 보호·제출·채점, 해커톤 평가·마감, 게시판·문의·도움 요청,
게스트 토큰 격리, 통계, 비활성 계정, 읽기 전용 관리자 화면, service-role 작업 권한.

## 운영 배포 순서

대상은 Supabase `ugelgndotyppgksbubot`, Vercel `lms-axopenlab`이다.
GitHub push만으로 Vercel에 자동 배포되지 않는다 (`PROJECT_LINKS.md` 참조).

1. 현재 원격 마이그레이션과 로컬 이력 일치를 확인하고 원격 스키마·백업 상태를 보관한다.
2. 테스트와 빌드를 통과한 `signup`, `admin-users` Edge Functions를 배포한다.
3. 새 마이그레이션 `20260928010000_admin_tenant_isolation.sql`을 적용한다. 이 파일 전체는 한 트랜잭션이며
   잠금 대기 5초, 구문 실행 120초를 넘으면 실패한다. 실패 시 적용 여부와 이력을 확인한 뒤 재시도한다.
4. Vercel 프로덕션을 배포하고 실제 운영 URL과 새 에셋 해시를 확인한다.
5. 운영에서 슈퍼관리자 전체 조회와 일반 관리자 범위, 마스터 복사, 가입 코드, 파일 다운로드를 확인한다.
6. 성공한 배포 URL·커밋·마이그레이션 버전을 기록한다.

마이그레이션은 운영 데이터를 삭제하는 `db reset`으로 적용하지 않는다. 문제가 생기면 접근 경계를
넓히는 이전 RLS로 되돌리지 말고 해당 오류를 수정하는 후속 마이그레이션을 사용한다.
네트워크·배포 자격 증명에 접근할 수 없는 환경에서는 로컬 검증 완료와 운영 배포 완료를 구분해 보고한다.
