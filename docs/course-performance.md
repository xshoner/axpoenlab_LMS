# 강좌 조회 성능 진단 및 개선 (2026-09-28)

## 원인

1. 관리자 격리 RLS가 `to_jsonb(전체 행)`을 권한 함수에 전달했다. 본문을 반환하지 않는
   목록에서도 이미지가 포함된 TOAST 본문을 읽고 JSON으로 변환했다. 첨부·평점의 상위 강좌를
   검사할 때도 같은 작업을 반복했다.
2. 동일한 요청 안에서 사용자 역할·기수 소유권을 행마다 다시 조회했다.
3. 학생 상세 화면이 본문, 전체 강좌 이동 목록, 개인 별점, 집계 별점 요청을 모두 기다렸다.
   본문이 준비돼도 다른 조회가 느리면 로딩 화면이 유지됐다.
4. 부가 정보가 도착할 때마다 변경되지 않은 큰 HTML도 다시 정화했다.

## 변경

- 권한 함수에는 소유자·기수·관계 ID만 전달한다. 제한 정책과 기존 공개/비공개 정책은 유지한다.
- 현재 요청에서 접근 가능한 기수/강좌 ID를 한 번 계산해 사용한다. 세션 간 캐시하지 않으며,
  슈퍼관리자의 관리자 화면 확인 헤더도 매 요청에 반영된다.
- 평점 집계의 접근 범위 검사도 동일한 집합을 사용한다.
- 학생 본문을 먼저 표시하고 평점과 응답 상태를 따로 갱신한다. 이전·다음 강좌는 현재 그룹만 조회한다.
- HTML 정화 결과를 본문 변경 때만 다시 계산한다. HTML 정화 자체는 생략하지 않는다.

## 운영 데이터 측정

운영 DB의 동일한 트랜잭션·계정·데이터에서 각 SQL을 전후 3회씩 `EXPLAIN ANALYZE`로 실행한 평균이다.
후보 스키마 변경은 이 측정 후 전부 롤백했다. 네트워크 전송·브라우저 렌더링·사용자 체감 총시간이 아니다.

| 조회 | 기존 DB 시간 | 개선 DB 시간 |
| --- | ---: | ---: |
| 슈퍼관리자 마스터 강좌 목록 | 227.48ms | 3.55ms |
| 슈퍼관리자 기수별 강좌 목록 | 103.63ms | 4.90ms |
| 학생 전체 강좌 이동 목록 | 1,069.08ms | 4.43ms |
| 학생 별점 집계 | 96.58ms | 4.34ms |
| 학생 단일 본문·첨부·설문·퀴즈 조회 | 3.81ms | 5.35ms |

단일 본문 SQL 자체는 원래도 빨랐다. 학생 화면의 주된 개선은 느린 부가 요청 제거와 대기 분리다.
강좌 이동 목록의 공유 버퍼 접근은 9,003회에서 88회로 감소했다.
`supabase/tests/course_performance.sql`로 배포 후 현재 시간을 다시 측정할 수 있다.

## 안전성 및 남은 개선

- 전체 마이그레이션·권한 회귀 테스트를 수행한다. 모든 테스트 행·역할에서 최적화 정책과
  종전 정책의 허용 결과가 동일한지 비교한다. 비공개 강좌/첨부/퀴즈, 비활성 계정도 검사한다.
- 이번 마이그레이션은 정책·함수만 변경한다. 기존 본문·회원·기수·파일을 수정하지 않는다.
- 측정 시 기수 강좌 219개 중 12개에 인라인 이미지가 있었고, 가장 큰 HTML은 약 7MB였다.
  큰 강좌의 전송 시간은 여전히 회선 속도의 영향을 받는다.
- 후속 콘텐츠 최적화는 인라인 이미지를 파일로 분리하고 URL로 참조하는 방법이다. 기존 원본을
  보존한 복제본에서 화질·권한·화면을 비교한 뒤 적용해야 하므로 이번에는 기존 본문을 변환하지 않는다.
